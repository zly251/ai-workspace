# 01 · 我的 AI 工作台：三个 Agent 怎么分工

## 结论先行

一个 Agent 想同时干"想清楚、写出来、验收好"三件事，结果通常是三件都干得半吊子。我的做法是**按能力切成三个角色，各自只干最擅长的那段**。

| 角色 | 工具 | 长处 | 短板（所以要别人接） |
|---|---|---|---|
| 架构师 | Claude Code | 长上下文、能通读整个代码库、写方案严谨 | 亲自动手改大批文件时不如专门工具稳 |
| 执行者 | Codex | 真写文件、真跑命令、真跑测试，闭环快 | 独立做大架构判断容易跑偏 |
| 编排者 | DeepSeek Harness | 长任务、批处理、连知识库、调度子代理 | 单点深读不如 Claude Code |

## 一条需求的实际流转

举个真事：给一个 Python + Node 的求职助手项目做「core 层抽取重构」。

1. **Claude Code 读架构**：让它通读 `src/`，指出 `distance.js` / `salary.js` 里混着业务逻辑和纯计算，建议抽 `core/` 契约层 + `modules/` 业务层。
2. **Codex 落地**：给它明确的文件清单和验收标准（"抽完后 `npm test` 必须全绿"），它真去改文件、跑测试、修到绿。
3. **DSH 串流程 + 验收**：跑全量测试拿证据（exit code、各套件通过数），再跑静态守卫（"core 不能 import modules"这类规则脚本），确认结构真的干净，最后提交、写交接。

**关键：每一步的产出都是下一步的输入，而且都有可核对的证据**（不是"我觉得改好了"）。

## 为什么不用一个"全能 Agent"

- **上下文会被撑爆**：让一个 Agent 又读全库又写全库，读到一半就忘了开头。
- **自己验收自己有偏**：写代码的和判对错的应该是两个脑子。
- **模型会变**：不同任务的最优模型不一样，绑死一个工具等于被一个供应商绑架。

## 协作规范（让我能同时用三个 Agent 而不乱）

1. **单负责人**：同一时间只允许一个 Agent 把某个任务标成"进行中"，其余只读或等待，避免并发改同一批文件。
2. **交接必留痕**：换手时留一条固定格式的记录——已完成 / 证据 / 下一步 / 风险。下一个 Agent 接手先读它，不重新猜背景。
3. **开工前拷问**：动手前先把「目的 + 验收标准」问清楚，用户点头才开工。宁可多问一句，不要猜错方向白干。
4. **结果入库**：每个实质任务的结论都写回知识库，而不是只留在聊天记录里。

## 一句话

> 多 Agent 的价值不在"人多力量大"，而在**角色隔离**——规划的不执行、执行的不自评、验收的看证据。
