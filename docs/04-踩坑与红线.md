# 04 · 踩坑与红线

这一篇专门记"踩过才知道"的坑，和几条**绝不越过**的红线。用 AI 干活最容易翻车的地方，往往不是它不会写代码，而是它在细节上自作主张。

---

## 坑 1：AI 说"已完成"，可能只是"看起来完成"

**症状**：Agent 回一句"已修复所有问题"，你一验，测试根本没跑，或者只跑了它自己挑的那两个。

**对策**：要求**可核对的证据**——命令原文、exit code、测试通过数。验收的人看证据，不看他怎么说。

## 坑 2：免费模型会"今天好好的，明天就没了"

**症状**：任务跑到一半全线 429，或者某个模型名突然服务端返回 `model not found`。

**对策**：见 [03 · 免费模型池](./03-免费模型池与每日体检.md)。四档管理 + 两层验收 + 每天探活。

## 坑 3：桌面端 AI 会"污染你的工作区"

**症状**：让 ChatGPT 桌面 App（Codex）做测试，它在你项目根目录建了一堆临时文件，还自动 git commit 了。

**对策**：让它干活时**显式指定子目录**，别把整个仓库根目录交给它。做完顺手 `git status` 看一眼。

## 坑 4：中文渲染成方框

**症状**：用脚本生成带中文的图片，中文全是 □□□。

**对策**：字体别用默认的西文字体（如 segoeui），改用系统中文字体（Windows 上是 `msyhbd.ttc` / `msyh.ttc`）。

## 坑 5：反复跳转会把网站惹毛

**症状**：在内置浏览器里反复 goto 同一个登录页，结果被限流、弹验证码、页面"一直闪"。

**对策**：能用点击页面上的链接导航，就别暴力 goto；被限流了就停手，越试越糟。

## 坑 6：写文件权限的"看不见的墙"

**症状**：某个 Python 解释器写 A 盘成功、写 B 盘全部 PermissionError，代码本身没问题。

**对策**：别跟它较劲。**换个能写的位置生成，再复制过去**，比改权限省事。

---

## 红线

> 这几条不是"建议"，是**底线**。

1. **不把判断权交出去**：AI 可以给方案、给建议，但"要不要做、做成什么样"必须人拍板。它说"这样最好"不算数。
2. **不碰付费凭据的默认路由**：给任何自动化配默认模型时，**必须显式写免费路由，禁止留空**——留空会静默回落到付费 API，一天能漏走真金白银。
3. **不自作主张扩大范围**：让它改 A，它顺手把 B 也重构了——这种"好心"最危险。范围外的改动必须回来问。
4. **不留无证据的"完成"**：没跑过的测试、没验证的结论，一律当作没做。

---

## 一句话

> 用 AI 干活，**最大的风险不是它笨，而是它太自信**。所以流程里每一步都要有"拿证据说话"的卡点。
