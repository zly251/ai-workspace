# 03 · 免费模型池与每日体检

## 为什么要有"模型池"

我日常跑的自动化多、模型消耗大，全用付费 API 成本受不了。做法是**建一个免费的模型池**：把各家能白嫖的额度聚合起来（自建反代 + 官方免费额度），按稳定性分档，每天探活一遍，坏的踢掉、好的补进下拉。

## 四档分类

| 档位 | 含义 | 处理 |
|---|---|---|
| 🟢 免费 | 零计费，长期可用 | 主力，随便用 |
| 🔵 限免 | 活动期免费，**有截止日** | 标明到期日，到期前迁移 |
| 🟡 积分 | 扣积分，标倍率 | 兜底，看性价比 |
| 🔴 不可用 | 服务端下架 / 真死 | 立刻从下拉删除 |

**必须区分两种"不能用"**：
- **今日额度用尽**（如 `429 Free usage limit reached`）＝可恢复，明天重置，**不要删**；
- **服务端下架**（如 `model service info not found`）＝真死，**立刻删**。

## 两层验收（重点）

只看 HTTP 探活会误判，必须两层：

1. **第一层 · HTTP 探活**：对每个模型发一个极小的请求（1~8 token），看是否返回、耗时多少。快速筛掉真死的。
2. **第二层 · 真 agent 冒烟**：用一个真子代理跑一个真实小任务（比如"读某个文件第 N 行并原文返回"），看它能不能完整走完工具调用链。

> **教训：第二层失败 ≠ 模型不可用。** 第一层全 LIVE、第二层却失败的，多半是子代理链路偶发整轮暴毙，同一模型重跑一次常能活。**不要据此下架模型。**

## 每天要做的事

- [ ] 全池探活，更新四档标签（写进模型下拉显示名：`档位·限流·到期日·模型名`）
- [ ] 每个免费模型标清「免费到什么时候」（查不到就写"暂无/长期"）
- [ ] 搜一遍有没有新增的免费模型，能用的补进下拉，暂不可用的记入"候选区"
- [ ] 记一条当日清单，和前一天对比，看哪家在悄悄收紧

## 为什么值得每天干

免费额度是**易碎品**：今天能用的免费模型，明天可能下架、可能涨价、可能改成限免到期。每天花十分钟体检，比某天任务跑到一半突然全线 429 然后再手忙脚乱排查要划算得多。

## 一句话

> 免费模型池不是"薅一次就跑"，而是一个**需要每天浇水的小花园**——探活、标注、补新、踢死，四件事循环。
